# 設計メモ（サーバー・将来拡張）

MVPではサーバーコストを最小化するため、契約・オプション・特典・端末・
タスク・家族メンバーはすべて端末内SQLite（`sqflite`）に保存しています。
一方で、以下の機能は性質上サーバー（またはストア提供のサービス）が
必要になるため、MVPでは「未接続だが差し替え可能」な設計にしています。

## 現状（MVP）と将来のデータ配置

| データ | MVPでの保存場所 | 理由 |
| --- | --- | --- |
| users（アカウント） | なし（端末ローカルのみ、匿名） | サーバー費用・個人情報を増やさないため |
| contracts / options / benefits / devices / tasks / family_members | 端末内SQLite | 小容量の構造化データのみ。契約書・画像は保存しない |
| subscriptions（課金状態） | 端末内キャッシュ（SharedPreferences）＋ストア（App Store/Google Play）が真実の情報源 | レシート検証はストアSDKに委譲 |
| calendar_connections | 端末内（Googleサインイントークンはgoogle_sign_inが管理、パスワードは扱わない） | OAuthトークンをアプリサーバーに送らない設計 |
| notifications | 端末内ローカル通知のみ | サーバーからの常時プッシュを避ける（#38） |
| settings | 端末内SharedPreferences | 小容量キーバリューのみ |

## 家族共有（プレミアム）を複数端末で同期する場合

現在の家族管理（`FamilyScreen`）は同一端末内のデータ整理（メンバーごとの
タグ付け）にとどまります。複数端末間で家族データを共有する場合は、
軽量なサーバーレスバックエンド（例: Supabase / Firebase の無料〜低額枠）
を追加し、`users` / `subscriptions` / `calendar_connections` /
`family_members` をサーバー側に持たせる構成に拡張してください。
契約・オプション・特典・端末などの構造化データはそのまま同じスキーマを
流用できるよう、各モデルに安定したUUIDを付与しています（`#45`）。

## 簡易管理画面（#49, #50）

運営者向けの管理画面（総ユーザー数・無料/体験/プレミアム内訳・
月間売上など）は、サーバー側でユーザー・課金データを集計する必要が
あるため、モバイルアプリの範囲外です。将来サーバーを追加する際は、
このリポジトリの `src/app/admin` 配下にある既存の管理画面パターン
（Next.js + Prisma + next-auth）を参考に、別プロジェクトとして
構築することを想定しています。

## 将来のAI機能（#7, #56, #57）

初期版ではAI解析・OCR・契約書アップロードを一切実装していません。
将来追加する場合に備えて、各データモデルには安定したUUIDを持たせており、
「AI解析結果から `ContractOption` / `Benefit` / `Device` を一括生成し、
ユーザー確認後に `AppRepository.upsertOption` 等でまとめて保存する」
という流れに自然に接続できる設計にしています。AI機能追加時は、
利用回数制限・レート制限をサーバー側のAPIゲートウェイで実装してください。

## Googleカレンダー以外のカレンダー連携（#58）

`GoogleCalendarService` はカレンダー連携の実装を1箇所に閉じています。
Apple/Outlookカレンダー対応を追加する場合は、同様のインターフェース
（`upsertEvent` / `deleteEvent`）を持つサービスクラスを追加し、
`AppRepository` から呼び分ける構成を想定しています。
